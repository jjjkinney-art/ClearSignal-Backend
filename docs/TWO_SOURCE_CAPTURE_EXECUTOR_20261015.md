# Separate two-source diagnostic capture executor

This change implements the executor proposed in PR291. It creates no authority,
performs no live capture during validation and does not resolve either product
gap. Hosted CI and exact-diff review remain necessary before preparing any new
single-use approval package. All nine historical approvals remain consumed.

## Fixed scope and origin binding

`validation.source_capture` permits exactly one ACHC Company Facts GET and one
NPK annual document GET, using PR291's exact URLs, 16,777,216 / 15,000,000 byte
envelopes, and distinct nontransferable ledger slots. There is no URL, limit,
retry, redirect, discovery or model option. Zero model attempts/tokens. No FMP,
NewsAPI or FRED. Existing six-case policies and production application paths are
unchanged. The only shared change is explicit support for this new fixed purpose
in schema-2 policy reconstruction, native-dispatch admission and reporting.

The NPK URL/form/date were checked against primary E5/E6 references in the saved
PR289 artifact SHA256
`b5210bd5965b8ef28ed6e728b1ea11527d34a6df126b1a1ebd99171aafb103e4`:
CIK 80172, 10-K filed 2026-03-13,
`https://www.sec.gov/Archives/edgar/data/80172/000143774926008214/npk20251231_10k.htm`.
The fixed manifest includes this artifact hash. A new capture does not
independently authenticate the historical artifact or retrospectively establish
what the earlier ACHC response contained.

## Approval and execution

Preparation is credential-free and network-free:

```
python -m validation.source_capture --prepare --execution-config REVIEWED_CONFIG.json \
  --output-dir FRESH_ABSOLUTE_OUTPUT --manifest FRESH_MANIFEST.json
```

Preparation writes only an exclusive manifest; it creates no approval, output
folder or ledger. Configuration retains the existing explicit proxy/CA contract,
including its unused bearer placeholder presence and reflection checks; this
must be disclosed in the separately validated execution configuration. No model
endpoint is available to the capture owner.

Execution requires a separately supplied approval file containing exactly
`reference`, `run_id`, `manifest_sha256`, `output_dir`, `execution_allowed`,
`spending_authorized`, and `public_body_retention_authorized`. All three flags
must be true; the canonical manifest binds source revision/hash, configuration,
exact sources/limits, retention, deadlines and the canonical output path.

```
python -m validation.source_capture --manifest REVIEWED_MANIFEST.json \
  --approval SEPARATE_SINGLE_USE_APPROVAL.json
```

These are command templates, not an approval package or execution instruction.
No approval has been generated by this change. US$0.52 remains a ledger allowance,
not an invoice ceiling or assurance about charges. Actual charges are unverified.

The launcher verifies pinned CPython 3.11.9/dependencies, source/configuration and
runtime presence before creating a fresh 0700 directory. The child receives an
allowlisted environment and empty isolated home; ambient dotenv/netrc access,
server entrypoint imports, subprocesses and writes outside its output are blocked.
It rechecks source/dependency/policy binding and creates its ledger exclusively.
The child audit hook admits sockets/DNS only through the existing claimed
ExchangeGate and scoped proxy/TLS backend. This is cooperative assurance, not a
sandbox for adversarial arbitrary Python. Tests replace only native I/O below
that boundary with invented HTTP protocol bytes.

## Transport, supervision and retained data

The owned transport retains strict HTTP 200, identity encoding, declared/observed
size, bounded 64-KiB reads, reflection/canary checks and immediate overflow close.
NPK is restricted to 15,000,000 bytes instead of the transport's ordinary 16 MiB;
no reviewed 30-MB authorization is minted. Exact media must be application/json
or text/html respectively. Requests have no Authorization header. Proxy/CA and
runtime values are checked again before exchanges; the model host is fenced out.

Each source has the existing 20-second source-evidence wall limit, with a bounded
three-second drain. The whole isolated process retains the 480-second deadline;
owned operation/inactivity timeouts remain 10 seconds. Claims/native dispatches
are durable and at most once. On any failure, stop without transferring unused
slots. Reopening a ledger fences execution; there is no resume/reset entrypoint.
Late tasks are tracked, gates sealed, and only the supervisor can publish/settle.
A late child exits after publishing its halted terminal artifact rather than
waiting indefinitely in executor atexit. A launcher timeout/nonzero exit produces
a separate launcher-failure verdict; it never replaces existing terminal evidence
or reopens the ledger. A hard-killed worker may leave claims ambiguous for review.

Successful source handling exclusively writes the bounded public body, a safe
receipt and derived analysis. Receipts contain only the fixed URL, HTTP status,
normalized media/encoding, byte count/hash, UTC capture time, attempt ID and request
fingerprint. No raw headers, contact, credentials or exception messages are saved.
Derived text receives additional reflection screening after normalization.
Publication failure can leave partial files; terminal success requires completed
publication and settled claims for both sources. Partial files are not evidence
of completion. Prior artifacts are never overwritten.

The receipt is a bound-code capture account, not independent origin verification.
Body retention is NEW scope requiring explicit approval. Parsing these sources
for diagnosis does not run the application's evidence-admission/hash path and
never admits a quotation or financial claim. Existing application validation
remains mandatory before any later product evidence admission. A local body hash
is not a reviewed canonical filing hash. The retained body envelope does not bound
process RSS: immutable copies, parsing, normalized text and diagnostics add memory.
No raw data has been collected to measure actual filing latency or memory here.

## Validation and remaining work

Tests use invented responses and approval/configuration values only, with real
sockets denied. They cover both fixed byte boundaries with declared, absent and
chunked framing; malformed lengths; media/encoding/JSON/identity rejection;
credential reflection in bodies and derived analysis; exact receipts; source/
quota/approval mutation refusal; at-most-once dispatch; timeout before and after
claim; late publication/settlement fencing; reopening refusal; and the isolated
worker's full successful path. Existing transport/ledger/approval regressions
must pass alongside them. No previous run files are modified by these tests.

After independent review and hosted CI, prepare a new exact merged-code/config/
manifest/output-bound package in the approved execution environment. Stop for
separate approval covering the new retention. After one capture, stop and use the
saved bytes to investigate demonstrated ACHC/NPK defects offline. This executor
is diagnostic preparation, not a larger-universe quality benchmark or launch gate.
