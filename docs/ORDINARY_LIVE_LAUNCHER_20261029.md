# Ordinary twelve-case pilot: approval-gated live launcher

This adds the live launcher for the twelve-case ordinary executor built in
PR #350. **Live execution is off by default.** A live run needs all of the
following:

- an execution package bound to the exact running code and to completed cost
  and retention evidence;
- a separate approval naming that package's digest and a fresh output
  directory;
- this host configured with the reviewed proxy and pinned CA, the SEC contact
  and the zero-model placeholder;
- the explicit `--execute` flag.

No live request was made while building or testing it. The live code path was
exercised only against a loopback server on 127.0.0.1 that holds a per-run
test CA.

No approval exists for this pilot. Every approval in this repository's tests
is an invented record.

Nothing about the limits changed. The run is still bounded by:

- 66 SEC GETs in total: 8 per thesis case and 3 per threshold case, including
  one routing directory slot per case;
- 10 dispatches per second and 4 concurrent;
- a 16 MiB cap per response body and 256 MiB of retained bodies in total;
- 30 s per thesis case, 20 s per threshold case and 480 s for the whole run;
- 0 model and 0 paid-provider attempts;
- no retries and no redirects;
- the frontend intent pin;
- the parent-side deadline kill, late-answer rejection and read-only export.

## Network configurations

The execution configuration must take exactly one of two reviewed shapes. Both
shapes share everything else:

- the gate's claimed, dispatched exchanges, with sockets admitted only by the
  gate's audit;
- certificate verification against a CA bundle pinned by canonical path and
  SHA-256, with hostname checking and `CERT_REQUIRED`;
- every limit and every approval rule.

**Explicit proxy** (historical, unchanged). All four proxy selectors must
equal `http://proxy:8080`. The historical `validation/pilot_approved.py`
validates and verifies this shape.

**Direct TLS (`substitution: "direct_tls"`, `proxy: null`).**

- **No application proxy.** If any of `HTTP_PROXY`, `HTTPS_PROXY`, their
  lowercase forms, `ALL_PROXY` or `all_proxy` is set, the run is refused. An
  inherited proxy is never overwritten.
- **The transport** uses `proxy=None`, `trust_env=False` and the pinned SSL
  context.
- **DNS.** Inside a claimed exchange, only that exchange's own SEC host on
  port 443 may be resolved. In approved mode, only globally routable answers
  are admitted (no loopback, private or shared address space).
- **Connections** may go only to the endpoints the gate resolved. No byte is
  written before TLS. TLS may use only the gate's pinned context with
  `server_hostname` equal to the claimed host, and a pooled connection cannot
  be reused for another host.
- **Test-only loopback.** Only the TEST-ONLY `loopback` worker maps the SEC
  hosts to 127.0.0.1:8443, and only it admits a loopback answer. The
  `approved` mode uses the system resolver and the public-answer rule, and the
  worker refuses an `approved` run under a TEST-ONLY approval.

Direct TLS avoids the *application* proxy. It says nothing about network
layers below the process, such as a VPN. A TLS interceptor whose CA is not in
the pinned bundle fails verification, and the run halts. It does not make the
run free of cost or prove where traffic exits.

## Graceful degradation (amendment, 2026-10-30)

The application gives up on slow evidence. `_collect_investment_evidence`
waits 10 s for every evidence task. On source-evidence answers it then waits
on for the two filing-document tasks, up to 20 s in total. It answers without
whatever is still pending. The pilot used to halt whenever that happened. It
now follows the same rule, under these constraints:

- **The same points.** A non-document task is abandoned when the first
  evidence wait ends. A document task is abandoned only if it is still
  pending after the application's extra wait. Agent and synthesis waits keep
  the historical halt.
- **Stopped, not orphaned.**
  - An abandoned stage's open exchange is stopped by the gate at its next
    I/O step (read, write, DNS or connect).
  - The stage may start no new request.
  - Its socket operations are refused without being counted as blocked
    external operations.
- **No late results.** A response that completes after the abandonment point
  is discarded, never admitted, retained or returned to the application. The
  gate stop and the discard each suffice on their own; removing both is
  caught by the tests. The only cross-stage state these evidence tasks write
  is the SEC directory and ticker caches, which are fed from responses, so
  they can hold only data that arrived in time.
- **Counted and terminal.**
  - An abandoned request keeps its reservation, its slot and its place in the
    concurrency count until its exchange has actually ended.
  - It then becomes `abandoned`, with its failure record and close time
    written in the same transaction.
  - Abandoned requests still count against every quota.
  - The export refuses an abandoned attempt that lacks that record, has a
    retained response, or closed after the next case began.
- **Closed before the next case.**
  - Every task, abandoned ones included, must end before the case can
    finish.
  - If one cannot be stopped within the case's remaining time (a hung peer
    that never yields a read), the case halts with `stage_timeout`, as
    before.
- **Outcome.** A completed case with any abandoned evidence is reported as
  `answered_degraded_unadjudicated`, counted as `degraded_answer`, and never
  as a quality pass.

One shared hook was added to `validation/pilot_boundary.py`:
`abandoned_task`, which returns `False` by default. Historical boundaries
therefore behave exactly as before; only the ordinary boundary overrides it.

**Rehearsal evidence.** The `evidence_abandoned` scenario uses a slow but
live peer, which delivers INGR's first company-facts response in 512-byte
reads one second apart. Result:
- INGR's thesis is degraded and the other cases are full answers, with no
  halt;
- the same 60 requests are made, each with a terminal outcome;
- the abandoned request is not retained, does not appear in the answer, and
  was closed before the next case started.

Under load, another case can also reach the application's 10 s window. Two of
about ten rehearsal runs showed `INGR:decision_threshold` degrading as well,
after an unexplained in-application gap of about 4.5 s. The tests accept that only as
a degraded answer with a complete accounting, never as a failure.

## Safeguards a live run must pass

`run` performs every check below, creates nothing and sends nothing, unless
`--execute` is given.

1. **Runtime.** CPython 3.11.9 and the audited dependency versions.
2. **Package equals the running code.** The package is recomputed from the
   git revision, the source hash of `app/**/*.py` and `validation/*.py`, the
   installed dependencies, the 12 cohort records and both evidence files'
   SHA-256. It must match exactly.
3. **Evidence is complete and current.** Each document's `derived` section is
   re-derived from the code and must be equal. Every operator attestation must
   be filled in, and no attestation may say test-only, TODO, TBD or pending.
4. **Separate approval.** The approval must name `digest(package)`, the
   package's output directory and its `all_in_usd`, with
   `execution_allowed: true` and `spending_authorized: true`. Any `TEST-ONLY`
   reference in the approval, the evidence references or the execution
   configuration is refused.
5. **Single use.** The approved output directory must not exist. The launcher
   creates it (0700), and a second run of the same approval is refused.
6. **No model or paid-provider spend is possible.**
   - `OPENAI_API_KEY` must equal the non-secret
     `ORDINARY-ZERO-MODEL-NO-CREDENTIAL`, so no model credential is present at
     all.
   - `FMP_API_KEY`, `FRED_API_KEY` and `NEWS_API_KEY` must be absent.
   - The boundary refuses every model request, and the gate admits only
     `www.sec.gov` and `data.sec.gov`.
7. **Network configuration.**
   - Either all four proxy selectors equal `http://proxy:8080` (explicit
     proxy), or none is set (direct TLS).
   - Both CA selectors must name the pinned bundle, whose bytes must match its
     SHA-256.
   - The SEC contact must be present and well formed.
8. **The worker re-checks independently.**
   - The `approved` mode requires a non-test approval for this exact
     directory, and `loopback` requires a test one.
   - The code and dependencies actually loaded must equal the policy.
   - The real proxy and CA check runs again.
   - Sockets are admitted only by the gate's audit, inside a claimed,
     dispatched exchange, to the address the gate resolved for `proxy:8080`.
   - TLS uses the pinned CA, with hostname checking and `CERT_REQUIRED`.

## Operator runbook (for after the human reviews)

```bash
python -m validation.ordinary_approved evidence-template --kind cost --all-in-usd <ceiling> --out cost.json
python -m validation.ordinary_approved evidence-template --kind retention --out retention.json
# Responsible humans complete every operator_attestations value; derived sections must not be edited.
python -m validation.ordinary_approved prepare --execution-config execution.json \
    --cost-evidence cost.json --retention-evidence retention.json \
    --output-dir /absolute/new/run-directory --package package.json
# Prints package_sha256. The approver writes approval.json, a separate record:
#   {"reference", "run_id", "manifest_sha256": <package_sha256>, "output_dir",
#    "all_in_usd", "execution_allowed": true, "spending_authorized": true}
OPENAI_API_KEY=ORDINARY-ZERO-MODEL-NO-CREDENTIAL SEC_USER_AGENT='<name> <contact email>' \
HTTP_PROXY=http://proxy:8080 HTTPS_PROXY=http://proxy:8080 http_proxy=http://proxy:8080 https_proxy=http://proxy:8080 \
SSL_CERT_FILE=<pinned CA> REQUESTS_CA_BUNDLE=<pinned CA> \
python -m validation.ordinary_approved run --package package.json --approval approval.json \
    --cost-evidence cost.json --retention-evidence retention.json          # checks only
# ...the same command with --execute performs the one approved run.
```

`execution.json` is the reviewed proxy configuration, in the same schema as
the historical approved pilots. It holds `documentation_reference`,
`verification_reference`, the fixed proxy and CA selectors, and
`ca_identity` (an absolute path and its SHA-256). It contains no credentials.

## Cost evidence

**Derived and re-verified by the launcher.** These come from the code and are
compared at run time:

- 66 SEC GETs at most, with the per-case maximums listed above;
- 10 per second and 4 concurrent;
- 480 s of wall time;
- a 16 MiB cap per response;
- body bytes read: an oversized response is read until the 64 KiB socket
  read that crosses the cap arrives, then refused. That allows at most
  16 MiB + 64 KiB per response and 66 × (16 MiB + 64 KiB) = 1,060.125 MiB in
  total;
- at most 256 MiB retained;
- 0 model attempts and 0 paid-provider attempts;
- no model credential present;
- destinations `www.sec.gov` and `data.sec.gov`, through the reviewed proxy;
- no retries and no redirects.

Each derived property names the offline tests that enforce it.

**Bytes on the wire are not bounded by this code.** On top of the body bytes
read, every request carries:

- a proxy CONNECT exchange;
- a TLS handshake with a certificate chain;
- HTTP request and response headers;
- TLS record framing and TCP/IP packet overhead.

A response that is refused or fails can also leave bytes already in flight or
buffered (the TCP receive window and TLS records) that were transferred but
never read. Egress and proxy cost estimates must add this overhead and an
in-flight margin to the 1,060.125 MiB body bound.

**What the code cannot verify, so humans must attest, with references:**

| Attestation | What a reviewer confirms |
|---|---|
| `sec_access_terms_reference` | SEC EDGAR's current access terms for these endpoints: no fee, the fair-access rate (the pilot never exceeds 10/s) and the declared User-Agent requirement |
| `proxy_and_egress_cost_reference` | The cost of the reviewed proxy or egress path for ≤66 requests: ≤1,060.125 MiB of body reads plus the protocol overhead and in-flight margin above |
| `compute_host_cost_reference` | The cost of the host for one run of ≤480 s |
| `provider_billing_check_reference` | That no model or paid-provider account can be billed by this run |

The ceiling the approver signs is `all_in_usd`. The policy keeps
`invoice_ceiling_verified=false`: the code never claims an invoice was
checked.

## Retention evidence

**Derived and re-verified by the launcher.**

- The output directory is created 0700.
- Its complete inventory is declared:
  - `request.json`, `ledger.sqlite` (plus a transient journal) and
    `worker.json`;
  - `packet.json`, the parent's fsynced record of all twelve outcomes. It is
    the ledger export, or twelve `not_run` outcomes when the worker stopped
    before creating its ledger;
  - an empty `isolated-home`;
  - two empty application store directories.
- The 14 ledger tables are listed.
- Only public SEC EDGAR content is stored.
- The SEC contact and the placeholder are never stored; retention and export
  refuse any record that contains them.

A test runs the live code path over loopback and asserts all of this:

- the directory holds nothing outside the inventory, at mode 0700;
- the store directories and `isolated-home` are empty;
- the ledger tables equal the declared list;
- no runtime value appears in any written file.

**Humans must attest:** `storage_location`, `access_control`,
`retention_period`, `deletion_procedure`, and `sec_content_terms_reference`
(the terms for retaining and using SEC content).

## Test evidence (offline)

- **Live code path over loopback.** The run used real sockets, 60 proxy
  CONNECTs and 60 TLS sessions verified against the pinned test CA. All 12
  cases were answered, through the `investment_thesis` pipeline. The run made
  60 wire entries, 0 blocked operations and 0 model requests, with at most 4
  in flight. Every request carried the declared User-Agent, and its Host
  matched the CONNECT target.
- **Unpinned certificate.** The handshake fails and no request is served.
  The run halts at the first exchange with `connect_error`, and all 12
  outcomes are reported.
- **Launcher refusal matrix.** 18 input changes are refused, covering:
  - the approval's digest, permission, spending flag, amount, test-only
    reference and directory;
  - code drift and amount drift in the package;
  - a missing attestation, a changed derived section, a pending attestation
    and changed evidence bytes;
  - an existing output directory;
  - a model credential, a paid-provider key and a missing SEC contact;
  - a changed proxy and changed CA bytes.
- **Other checks.**
  - `run` without `--execute` launches nothing.
  - An approval executes at most once.
  - `prepare` refuses test-only configuration.
  - A live mode requires an approval of its own kind.
  - Only the gate admits a socket, and only in a live mode.
- **Evidence binding.** `prepare` refuses tampered or unfinished evidence,
  and `run` refuses a ceiling that differs from the cost evidence. The
  committed templates must equal what the code derives.
- **Early worker failure.** A real worker that refuses before creating its
  ledger, run through `run --execute`, still leaves a durable `packet.json`
  in the approved directory with all twelve `not_run` outcomes. The command
  prints those same twelve and exits nonzero. Reverting to "write only when
  a ledger exists" fails this test.
- **Worker refusals.** A live mode refuses before any ledger or socket when
  the zero-model placeholder is missing, and refuses a TEST-ONLY approval in
  `approved` mode.
- **Mutation sweep.** 18 targeted mutations of the new safeguards were run.
  17 are caught by the tests. The 18th removes the launcher's explicit
  approval-directory check; it is equivalent, because the approval's digest
  already binds the directory and `policy_for` refuses a mismatch. One
  mutation was deliberately not run: making loopback use the system resolver
  would issue a real DNS query.
- **Direct TLS over loopback** (127.0.0.1:8443, a per-run test CA). There
  were 0 CONNECTs and 60 direct TLS requests. Every request's SNI and `Host`
  equalled the claimed SEC host, and all 12 cases were answered with at most 4
  in flight. Further results:
  - an unpinned certificate is refused before any request;
  - each of the six proxy variables, when set, is refused and left unchanged;
  - a changed CA bundle is refused;
  - the configuration shape is exact;
  - DNS for an unclaimed host, a non-HTTPS port, or a loopback, private or
    shared answer is refused;
  - an approved gate defaults to public answers only.

  Six targeted mutations of the direct-mode rules are all caught.
- **Regressions.** The rehearsal, ordinary and historical pilot suites pass
  unchanged: 14 files, one file per process, with CPython 3.11.9 and sockets
  refused.
