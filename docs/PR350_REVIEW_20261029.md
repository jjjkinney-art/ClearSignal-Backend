# PR #350 model-assisted review (2026-10-29)

This is a model-assisted review. It is not an independent human review and
does not satisfy the independent-reviewer prerequisite.

Branch `pilot/offline-ordinary-accounting`. Reviewed head `e7e340e`. Head
after fixes `86e8995`. Base main `2b31b14`. All verification was offline:
pinned CPython 3.11.9, the repository's pinned dependencies, external sockets
and DNS refused by an audit hook, an invented home directory, invented
approvals and invented SEC bodies. No live request, spend, deployment or
merge was made, and no approval was used.

## Confirmed defects (fixed)

1. **Blocker: frontend intent routed 7 of 12 cohort questions away from
   research.** The frontend always sends `intent` from `classifyQueryIntent`.
   At frontend main `86189b4`:
   - NPK (both questions) is classified `market_question`, because
     "Industries" is a macro keyword.
   - The five "What is…" thesis questions are classified
     `investing_education`.

   The backend treats both intents as authoritative
   (`app/services/company_detection.py:79`, and the general-finance fast path
   in `app/services/router_service.py`). It answers them with
   `run_general_finance_agent`, a model call. The rehearsal omitted `intent`,
   so it did not measure the path users take. A zero-model live pilot would
   have halted on case 1. Production users asking these questions get general
   answers today.

   Fixes:
   - **Frontend.** `Ai-Intelligence-interface` PR #86 (commit `b56cd0b`,
     branch `fix/company-research-intent`), `lib/queryIntent.ts` plus tests.
   - **Backend.** `validation/ordinary_frontend_intents.py` pins the frontend
     commit, the classifier and resolver hashes, the question-text hash and
     the per-case intents. `_ordinary_rehearsal_worker.py` sends them.
   - **Tests.** The pinned table is checked against the cohort. A
     `market_question` mutation for NPK halts the happy run.
2. **Medium: an answer the parent ruled late could be exported.** The fault
   was at `validation/ordinary_isolated_rehearsal.py`, in the
   parent-stop branch.
   - **Trigger.** The child commits `complete_case` just after the parent's
     case deadline, before the parent kills it. The supervisor checks its
     deadline before it reads messages, and the child's ledger clock starts
     after the acknowledgement.
   - **Consequence.** An answer past 30 s or 20 s was exported as
     `answered_unadjudicated`.
   - **Fix.** The interrupted case is marked halted, its answer is dropped
     and recorded in `late_answers_rejected`, and the packet is halted.
     Covered by a test.
3. **Low: a worker refusal before ledger creation reported no case
   outcomes.** The packet now reports all twelve as `not_run`.
4. **Low: a tautological root comparison** in
   `verify_running_configuration` was removed. It compared a value with
   itself.

Also added: a test in which a child is SIGKILLed while holding
`BEGIN IMMEDIATE` with an uncommitted answer. `record_parent_stop` rolls back
the hot journal before the read-only export, and the export shows nothing
from the open transaction.

## Verified without defect

- **Routing and identity.**
  - The NNBR legal-form fix was scanned over 854 repository question strings
    against 250 issuers, with decoys such as IT INC, US CORP, ON CORP, CA INC,
    AI CORP, GE CO and AT&T INC. Only 4 resolutions changed, and all 4 are
    correct.
  - A short name shared by two registrants, and a question naming two
    issuers, still resolve to nothing.
- **Execution capability.**
  - Only the worker constructs the boundary, and it hard-codes the synthetic
    backend.
  - Output reuse and reopen are refused.
  - A mismatched source hash or CA identity is refused before any ledger
    exists.
- **Quotas.** The routing stage admits only `sec/directory` ×1. Per-case
  totals are 8/3, the overall total is 66, and model and paid-provider
  attempts are 0. Exceeding the rate paces; exceeding concurrency halts.
- **Retention.** Body and receipt are retained before settlement. The limits
  are 16 MiB per body and 256 MiB in aggregate. Screening checks raw bytes,
  so a non-UTF-8 body is accepted, not halted.
- **Deadlines, export and tamper refusal.** These are covered by the existing
  tests, and the 11 tamper mutations are refused.
- **Suites.** 23 test files covering ordinary, pilot, identity, detection and
  intent were run, one file per process, and all pass.
  `test_pilot_approved.py` needs the macOS `/tmp` host adapter (66/66 with
  it). Without it, it fails identically on base.

## Accepted limitations (documented, not defects)

- Approval is self-asserted, not authenticated. Authenticated-mode
  configuration is not proof of authentication.
- `source_binding` covers `app/**/*.py` and `validation/*.py` only.
  Dependencies are bound by version, not hash, and the git revision is not
  verified in the worker.
- The DNS fixture neutralises the application's SSRF check inside claimed
  exchanges, by the historical design.
- Rate and concurrency are measured at owned HTTPX entry. Reservation, entry,
  socket and SEC arrival are distinct, and only entry is established.
- Each case assumes a fresh session with no `active_ticker`.

## Unresolved questions / prerequisites

- **There is no live entry point.** The worker hard-codes
  `OrdinarySyntheticSEC`, and the launcher has no live, resume or reset
  option. A live run therefore needs new, separately reviewed code: a
  launcher that builds the boundary over the real SEC backend. That code does
  not exist in this PR and was deliberately not written in this review. Any
  execution package must bind it, so it has to exist and be reviewed before
  the package can be assembled.
- **The deployed frontend is not checked mechanically.** The pinned intents
  are code-bound, but nothing confirms that the deployed frontend serves
  classifier hash `d8f9810f…41b6`. A human must confirm this when the package
  is approved.

- The frontend fix must be reviewed, merged and deployed. The approval
  package must name the deployed frontend commit, and that commit's
  classifier hash must equal the pinned one.
- Hosted frontend CI (`npm test`, `tsc`, build) runs only when a PR is
  opened. Locally, 314/316 lib tests pass. The two failures also fail on
  main, because npm packages were not installed (`npm ci` was not run).
- The prerequisites from the brief all remain open:
  - verified all-in cost and retention terms;
  - independent human reviewers;
  - Julian's approval of the final amended execution package.
